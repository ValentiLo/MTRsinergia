## 🔬 Лабораторная работа № 1. «Анализ и подбор конфигурации рабочей станции для разработки игр»

### Цель работы
Научиться анализировать требования игрового проекта и подбирать оптимальную конфигурацию аппаратного обеспечения под конкретные задачи (программирование, художественная работа, тестирование).

### Оборудование и ПО
- ПК с доступом в интернет.
- Таблицы характеристик CPU, GPU, RAM, SSD (предоставляются преподавателем).
- Онлайн-конфигураторы (DNS, Citilink, Regard) — для расчёта стоимости.
- Microsoft Excel / Google Sheets — для таблиц.

### Теоретическая часть
- Основные компоненты рабочей станции: CPU, GPU, RAM, накопители, БП, охлаждение.
- Различия требований для ролей: программист, художник, тестировщик, геймдизайнер.
- Понятия: **узкое место (bottleneck)**, **баланс системы**, **апгрейд-путь**.

### Задание

**Часть 1. Анализ требований**
1. Выберите игровой проект (Unity / Unreal Engine 5 / Godot).
2. Определите его **минимальные** и **рекомендуемые** системные требования (официальные источники).
3. Составьте таблицу требований.

**Часть 2. Подбор конфигураций**
1. Подберите **3 конфигурации**:
   - **Бюджетная** (до 80 000 ₽) — для студента/инди.
   - **Оптимальная** (до 150 000 ₽) — для профессионала.
   - **Профессиональная** (до 300 000 ₽) — для студии.
2. Для каждой укажите: CPU, GPU, RAM, SSD, БП, охлаждение, корпус.
3. Обоснуйте выбор каждого компонента.

**Часть 3. Сравнение**
1. Составьте сводную таблицу: конфигурация → цена → производительность → для кого.
2. Определите **узкие места** каждой конфигурации.
3. Предложите **путь апгрейда** для бюджетной конфигурации.

### Форма отчёта
- Титульный лист.
- Цель работы.
- Таблица требований проекта.
- 3 конфигурации с обоснованием.
- Сводная таблица сравнения.
- Вывод: какая конфигурация оптимальна и почему.

### Контрольные вопросы
1. Почему программисту и художнику нужны разные конфигурации?
2. Что такое «узкое место» и как его избежать?
3. Почему SSD обязателен для разработки игр?
4. Как рассчитать мощность блока питания?

## 🔬 Лабораторная работа № 2. «Настройка инфраструктуры для командной разработки игрового проекта»

### Цель работы
Освоить настройку базовой инфраструктуры для командной работы над игровым проектом: система контроля версий, сетевое взаимодействие, резервное копирование.

### Оборудование и ПО
- 2–3 ПК (или виртуальные машины).
- Локальная сеть.
- **Git** (или **Perforce** — по выбору преподавателя).
- **GitHub / GitLab** (аккаунт).
- **VPN-клиент** (OpenVPN, WireGuard).
- **Программа для бэкапа** (rsync, Veeam Free).

### Теоретическая часть
- Системы контроля версий: Git, Perforce, SVN — сравнение.
- Git LFS для больших файлов.
- Сетевое взаимодействие: LAN, VPN, пропускная способность.
- Резервное копирование: полное, инкрементальное, дифференциальное.

### Задание

**Часть 1. Настройка Git-репозитория**
1. Создайте репозиторий на GitHub/GitLab.
2. Настройте **Git LFS** для больших файлов (текстуры, модели).
3. Добавьте тестовые файлы (код + ассеты).
4. Сделайте несколько коммитов, создайте ветки, выполните слияние.

**Часть 2. Настройка сетевого взаимодействия**
1. Настройте локальную сеть между ПК.
2. Установите и настройте **VPN** для удалённого доступа.
3. Проверьте пропускную способность сети (speedtest, iperf).
4. Настройте **сетевые диски** для общих ресурсов.

**Часть 3. Резервное копирование**
1. Настройте **ежедневный бэкап** репозитория.
2. Проверьте **восстановление** из бэкапа.
3. Составьте **план резервного копирования** для студии.

### Форма отчёта
- Титульный лист.
- Цель работы.
- Скриншоты настройки Git, VPN, бэкапа.
- Таблица сравнения Git / Perforce / SVN.
- План резервного копирования.
- Вывод.

### Контрольные вопросы
1. Чем Git LFS отличается от обычного Git?
2. Зачем нужен VPN в командной разработке?
3. Какие бывают типы резервного копирования?
4. Почему Perforce популярен в игровой индустрии?

## 🔬 Лабораторная работа № 3. «Анализ и оптимизация производительности игрового проекта»

### Цель работы
Научиться анализировать производительность игрового проекта, выявлять узкие места и оптимизировать его под разные конфигурации оборудования.

### Оборудование и ПО
- ПК с установленным **Unity** или **Unreal Engine**.
- Готовый игровой проект (предоставляется преподавателем).
- Инструменты профилирования:
  - **Unity Profiler** / **Unreal Insights**.
  - **MSI Afterburner**, **GPU-Z**, **CPU-Z**.
  - **RenderDoc** — для анализа кадров.
- Microsoft Excel — для таблиц.

### Теоретическая часть
- Метрики производительности: **FPS**, **frame time**, **draw calls**, **polygon count**.
- **CPU-bound** и **GPU-bound** проекты.
- Оптимизация: LOD, occlusion culling, batching, texture compression.
- Тестирование на разных конфигурациях.

### Задание

**Часть 1. Замер базовой производительности**
1. Откройте проект в Unity/Unreal.
2. Запустите **Profiler** и запишите метрики:
   - Средний FPS.
   - Время кадра.
   - Количество draw calls.
   - Загрузка CPU и GPU.
3. Составьте таблицу базовых метрик.

**Часть 2. Выявление узких мест**
1. Определите, что нагружает систему больше — **CPU или GPU**.
2. Найдите **самые тяжёлые операции** (рендеринг, физика, скрипты).
3. Составьте список проблемных мест.

**Часть 3. Оптимизация**
1. Примените **3–5 оптимизаций**:
   - Снижение качества текстур.
   - LOD для моделей.
   - Occlusion culling.
   - Батчинг материалов.
   - Упрощение шейдеров.
2. Замерьте метрики **после оптимизации**.
3. Составьте таблицу «до / после».

**Часть 4. Тестирование на разных конфигурациях**
1. Запустите проект на **3 конфигурациях** (бюджетная, оптимальная, профессиональная).
2. Запишите FPS на каждой.
3. Определите **минимальную конфигурацию** для комфортной игры.

### Форма отчёта
- Титульный лист.
- Цель работы.
- Таблица базовых метрик.
- Список узких мест.
- Таблица «до / после» оптимизации.
- Результаты тестирования на разных ПК.
- Вывод: какие оптимизации дали наибольший эффект.

### Контрольные вопросы
1. Что такое draw call и почему их количество важно?
2. Чем CPU-bound проект отличается от GPU-bound?
3. Что такое LOD и occlusion culling?
4. Как определить минимальную конфигурацию для игры?
